# Commerce 7.95G2-G3 — Cart operations and calculation

## Scope

G2 makes `CommerceCartService` the sole mutation boundary for the active cart:

- add a product;
- update a quantity;
- remove a line;
- clear the cart;
- refuse products already owned;
- keep duplicate single-unit additions idempotent.

G3 keeps all monetary resolution in `CommerceCartCalculator`. Prices are read again from the Native catalogue for every snapshot. Current totals expose subtotal, discount, tax and total; discount and tax intentionally remain zero until their dedicated engines are introduced.

## Quantity rules

The engine remains quantity-capable. Current course access and digital products default to `1..1`. A product may explicitly opt into a range through catalogue metadata.

## Compatibility

The existing G0-G1 constructor remains compatible: catalogue and ownership dependencies added to `CommerceCartService` are optional for read/open/snapshot operations. Mutation methods fail explicitly if no catalogue gateway is wired.

## Persistence

No database table and no plugin version bump are introduced. Active carts remain session-backed through the repository abstraction.
