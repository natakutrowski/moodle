# Commerce 7.95F7E–F7H — Final certification

## F7E — Residual consistency cleanup

`cleanup_795f7e_orphan_payments.php` is dry-run by default. It only targets rows in
`local_subscriptions_commerce_payment` whose `purchaseid` no longer exists.

Execution requires the explicit confirmation token:

```bash
php local/subscriptions/cli/commerce/cleanup_795f7e_orphan_payments.php \
  --execute \
  --confirm=DELETE-ORPHAN-PAYMENTS
```

Run F7C again immediately after cleanup.

## F7F — Storefront source integrity

The F7F audit verifies the public storefront templates, shared badge renderer,
product page templates, responsive stylesheet markers and Gustave renderer.
It performs no database write.

```bash
php local/subscriptions/cli/commerce/audit_795f7f_storefront_ux.php
```

## F7G — Global certification

```bash
php local/subscriptions/cli/commerce/certify_795f7.php
```

The global command runs F7A, F7B, F7C, F7D and F7F. A non-zero exit code means
that the storefront is not certified.

## F7H — Release-candidate checklist

Before tagging the release candidate:

1. All F7 PHPUnit tests pass.
2. `certify_795f7.php` prints `STOREFRONT CERTIFIED`.
3. Native Gate is green in full scope.
4. DEV-only feature flags are reviewed.
5. A production backfill dry-run is archived.
6. Database and Moodledata backups are verified.
7. The rollback command sequence is written and tested on DEV.
8. No destructive cleanup command is included in the deployment procedure
   without a fresh dry-run and explicit confirmation.

No plugin version bump or database migration is introduced by this lot.
