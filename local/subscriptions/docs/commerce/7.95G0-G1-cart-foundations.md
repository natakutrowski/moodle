# Commerce 7.95G0–G1 — Cart foundations

## Scope

This batch introduces the Native Commerce cart domain and its first runtime. It does not add storefront controls, cart mutations or checkout integration yet.

## Architecture

The cart stores only stable references:

- product SKU;
- Native price ID;
- quantity;
- optional line metadata.

Names and monetary values are resolved again from the Native catalogue whenever a snapshot is calculated. The Purchase remains the contractual frozen record.

## Quantity policy

The engine supports integer quantities greater than one. Catalogue products nevertheless default to the `single` policy, which accepts exactly one unit.

Future products may opt in through catalogue metadata:

```json
{
  "quantity_policy": "range",
  "min_quantity": 1,
  "max_quantity": 10,
  "quantity_step": 1
}
```

The policy is enforced in the calculator and will be reused by G2 mutations and the final pre-Purchase validation.

## Persistence

G1 uses Moodle session persistence only. No database table and no upgrade step are introduced. The repository contract already allows a later abandoned-cart SQL implementation.

## Runtime flow

```text
Native Catalog
    ↓
CommerceCartCatalogGateway
    ↓
CommerceCartCalculator
    ↓
CommerceCartSnapshot
```

`CommerceCartRuntimeFactory::create()` exposes the production session-cart service graph.

## Deferred to G2+

- add/remove/update commands;
- duplicate-line behaviour;
- ownership rules;
- bundle compatibility;
- Storefront UI;
- cart-to-Purchase conversion.
