# Commerce 7.95G8 — Cart & Promotion certification

## Status

Phase 7.95G is functionally complete. G8 freezes the public contracts created by the Cart and Promotion work and prepares their consumption by 7.95H Unified Checkout.

## Certified scope

- Native Cart domain and session repository.
- Cart operations and quantity policies.
- Cart calculator, totals, messages and presentation.
- Manual promotion codes and automatic promotions.
- Promotion eligibility, adjustments and persistence.
- Storefront/cart integration.
- CRM promotion administration and Commerce configuration hub.
- FR, EN and RU presentation strings introduced by the phase.

## Promotion invariant

A manual promotion code is only persisted after a complete server-side calculation accepts it.

A rejected code therefore:

- does not alter cart metadata;
- does not create a promotion adjustment;
- does not change the cart total;
- is exposed through a structured operation message;
- is never reintroduced by a second snapshot in the mutation endpoint.

Replacing a valid manual code keeps exactly one `promotion_code` entry in cart metadata.

## API freeze

The following public contracts are frozen for the remainder of 7.95. Future work must extend them without breaking current callers:

- `CommerceCartPresenter::present()`;
- `CommerceCartService::apply_promotion_code()`;
- `CommerceCartService::remove_promotion_code()`;
- `CommerceCartService::snapshot()`;
- `CommerceCartCalculator::calculate()`;
- `CommercePromotionEngine::calculate()`.

Optional parameters must remain optional. Existing parameter names and order are part of the compatibility contract because Moodle integrations and tests may use named arguments or reflection.

## Security certification

Cart mutations remain server-side and require:

- Moodle session key validation;
- constrained `PARAM_*` input handling;
- local return URLs only;
- server-side catalogue and promotion validation;
- operation results as the authoritative source for notices.

Promotion administration remains protected by the existing CRM access guard and Moodle capability model.

## Performance certification

The promotion repository runtime cache remains the primary protection against repeated promotion lookups. Cart calculation performs one catalogue quote per cart line and one promotion evaluation pass per candidate. G8 introduces no additional database writes or recalculation pass.

## Pre-H contract

Unified Checkout may consume the following stable outputs:

- `CartSnapshot` as the immutable checkout input;
- cart subtotal, discount and Total TTC values;
- Promotion adjustments with promotion identity, code, amount and automatic/manual origin;
- structured cart messages;
- customer, currency, product and price identities;
- the accepted manual promotion code stored in cart metadata.

Checkout must freeze these values into the Purchase/payment request rather than recalculate them from browser input.

## Certification evidence

G8 adds a dedicated PHPUnit certification test covering:

- public API signatures;
- mutation endpoint security contracts;
- rejected-code invariants;
- availability of this pre-checkout contract documentation.

The previous G7C regression test is corrected to add an eligible cart item before validating replacement of two valid manual codes. This preserves the business invariant rather than weakening validation.
