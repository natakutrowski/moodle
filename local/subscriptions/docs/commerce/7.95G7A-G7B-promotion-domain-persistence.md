# Commerce 7.95G7A–G7B — Promotion domain and persistence

This batch introduces the Native Commerce promotion boundary without connecting it to the Cart calculator yet.

## Decisions

- Manual promotions require a normalized code.
- Automatic promotions may omit a code.
- Percentage values use basis points (`2000` = 20%).
- Fixed values use minor currency units.
- Eligibility is evaluated server-side for status, date window, currency, minimum cart amount, product scope and usage limits.
- Promotions and redemption evidence are persisted in Native Commerce tables.
- One manual code per cart and stacking orchestration are deferred to G7C–G7D.
