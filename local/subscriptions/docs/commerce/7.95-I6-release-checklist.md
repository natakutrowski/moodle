# CampusFR Commerce Transactional Mail Engine — Release checklist

## Automated certification

```bash
vendor/bin/phpunit \
  --testsuite local_subscriptions_testsuite \
  local/subscriptions/tests/commerce/mail

php local/subscriptions/cli/commerce/mail/certify_engine.php --strict
php local/subscriptions/cli/commerce/mail/certify_release.php
```

Expected final status:

```text
STATUS: CERTIFIED / FROZEN
```

## Functional matrix

Validate on DEV before PROD:

- Course Native;
- Digital Native;
- Bundle Native;
- mixed cart;
- Moodle user;
- Guest;
- FR, EN and RU;
- payment confirmed receipt;
- access message after successful fulfillment;
- pending, failed and cancelled templates;
- invoice attached to receipt;
- identical invoice from Order Details;
- immediate delivery without manual cron;
- temporary SMTP failure followed by cron retry;
- idempotent webhook replay;
- optional audit copies to `log@campusfr.fr`;
- no visible `cmp_*` reference.

## UX review

- Gmail desktop and mobile;
- Apple Mail where available;
- Outlook where available;
- images and header fallback;
- desktop and 390px CRM previews;
- readable plain-text version;
- CTA links and secure downloads;
- dark-mode readability;
- subject and preheader length.

## PROD readiness

Before deployment:

1. Back up database and plugin code.
2. Confirm Moodle cron is active.
3. Confirm SMTP configuration and support sender.
4. Run Moodle upgrade if required by prior I6 phases.
5. Purge caches.
6. Run `certify_release.php` on PROD.
7. Keep audit copies disabled until the address and policy are confirmed.
8. Perform one controlled low-value transaction.
9. Verify receipt, access mail and invoice.
10. Check the outbox contains no stale, overdue or failed records.

## Freeze decision

Once the checklist passes:

