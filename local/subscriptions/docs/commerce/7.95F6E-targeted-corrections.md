# Commerce 7.95F6E — Targeted corrections

F6E stabilises the product lifecycle page, access-scope configuration, Gustave badge rendering and transitional digital ownership.

## Lifecycle

`lifecycle.php` now passes the required page body class to `CrmPageConfigurator::configure()`.

## Shared access scope versus canonical migration mapping

Two relations are deliberately separated:

- `storefront product → effective access scope`: several Native products may reuse the same scope;
- `Legacy plan → canonical Native product`: one-to-one mapping preserved for production migration and idempotent backfill.

The shared scope is stored in product metadata under:

```json
{
  "access": {
    "sourceplanid": 30,
    "scopeid": 4
  }
}
```

Selecting a shared scope never transfers a Legacy mapping. Plans already mapped to another Native product remain unavailable in the canonical mapping selector.

## Legacy digital ownership

For `digital` and `digital_download` products, ownership is resolved through:

1. Native grants;
2. Native purchases;
3. the canonical mapping to `subscription_digital_product`;
4. a paid/completed Legacy record in `subscription_digital_payment_request` for the current Moodle user.

## Gustave badge

The custom Gustave icon receives a dedicated CSS class and a default size of `1.8em`.

## Production migration invariant

The future production backfill must preserve:

> one Legacy plan or Legacy digital product = one canonical Native product.

Additional commercial products may share access scopes, but must not duplicate canonical Legacy mappings.
