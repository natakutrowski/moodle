# CampusFR 7.98D — certification finale du retrait du Trial Legacy

## Objet

7.98D certifie la fermeture contrôlée de l'ancien parcours Trial sans supprimer les comptes,
la progression ni l'historique commercial. Les dates de transition sont des données
d'environnement Moodle et ne doivent jamais être codées dans Git.

- Date A : fermeture des nouvelles inscriptions Trial.
- Date B : fin de la fenêtre Legacy Trial et extinction des accès Trial non convertis.

La certification doit rester valable avec des dates DEV différentes des dates PROD.

## Gate automatisé

Depuis la racine Moodle :

```bash
bash local/subscriptions/tools/run_798d_trial_certification.sh
```

Le gate est non destructif. Il purge les caches, exécute les TU 7.98D des deux plugins,
les smokes Commerce nécessaires, puis termine par l'audit Trial `--strict`.
Il n'exécute jamais la commande d'expiration avec `--apply`.

La sortie détaillée est écrite dans `/tmp/campusfr-798d-certification-*.txt`.

## Invariants certifiés automatiquement

- A-1 seconde : inscriptions Trial ouvertes et conversion disponible.
- A exacte : nouvelles inscriptions fermées, conversion Legacy encore ouverte.
- B-1 seconde : conversion Legacy encore ouverte.
- B exacte : conversion Legacy fermée et phase `legacy_closed`.
- Le garde-fou de création manuelle bloque uniquement un plan Trial après A.
- Les plans payants restent créables après A.
- La conversion Trial Native, son pricing panier et son completion restent compatibles.
- Après B, la conversion Trial spéciale n'est plus résolue par le bridge Native.
- L'expiration Date B est idempotente.
- Les accès payants plus forts sont préservés lorsque les droits Trial sont retirés.
- La logique ownership/cart standard continue de refuser un produit déjà possédé.
- L'audit strict ne tolère aucune incohérence active Trial ni rôle Legacy résiduel.
- Les historiques Campus-only expirés restent de l'historique, pas une subscription à recréer.

## Matrice fonctionnelle manuelle finale

| Scénario | Résultat attendu |
| --- | --- |
| Nouveau visiteur avant A | CTA Trial visible et création possible. |
| Nouveau visiteur à partir de A | Aucun nouveau Trial ; ancien endpoint également bloqué. |
| Trial existant actif entre A et B | Accès gratuit jusqu'à sa propre échéance ; conversion A1 disponible. |
| Trial individuellement expiré entre A et B | Pas d'accès gratuit ; conversion A1 Legacy encore disponible. |
| Trial non converti après B | Plus d'accès Trial, plus de remise spéciale, compte toujours utilisable. |
| Trial converti avant B | Accès payé conservé ; aucune révocation du droit supérieur. |
| Client normal après B | Achat A1 standard inchangé. |
| Client possédant déjà A1 | Le mécanisme standard `already_owned` reste applicable. |
| CRM User360 | Statut clair : actif, expiré, converti ou historique Legacy. |
| Navigation CRM | Commerce → État du Trial Legacy accessible sans URL directe. |
| Admin après A | Le plan Trial n'est plus proposé/créable ; plans payants inchangés. |
| Mobile/storefront | Aucun CTA Trial résiduel après A ; achat standard reste utilisable. |

## Certification globale CampusFR

Après validation du gate 7.98D et de la matrice manuelle, exécuter également :

```bash
bash local/subscriptions/tools/run_campusfr_certification.sh
```

La phase 7.98D n'est clôturée qu'après gate ciblé, vérifications manuelles et certification
globale sans échec. Les PHPUnit Deprecations déjà connues restent hors périmètre de cette phase.
