# Периоды на панели CRM

Панель CRM в `local_subscriptions` позволяет анализировать текущую коммерческую и операционную активность по нескольким периодам.

Администратор может переключаться между режимами **Сегодня**, **Текущая неделя** и **Текущий месяц**.

## Сегодня

Период **Сегодня** включает события с начала текущего дня по часовому поясу Moodle.

Он подходит для контроля:

- новых пользователей;
- начатых пробных периодов;
- цифровых покупок;
- последних действий CRM;
- платежных ошибок;
- активности CRM Inbox.

Показатели могут меняться в течение дня.

## Текущая неделя

Период начинается с первого дня недели, заданного в настройках Moodle, и заканчивается текущим моментом.

Используйте его для:

- сравнения нескольких дней;
- анализа продаж;
- контроля нагрузки на команду;
- поиска повторяющихся аномалий;
- оценки активности пользователей.

## Текущий месяц

Период охватывает данные с первого числа месяца до текущего момента.

Он полезен для:

- месячной отчетности;
- анализа конверсии;
- контроля выручки по валютам;
- оценки профилей риска;
- анализа динамики покупок.

Это фактические данные, а не прогноз.

## Показатели Hero

Главный блок Dashboard может содержать:

- число новых пользователей;
- число пробных периодов;
- цифровые покупки;
- цифровую выручку;
- профили, требующие внимания;
- последние действия CRM.

При смене периода все показатели должны пересчитываться одновременно.

## Выручка по валютам

Выручку необходимо показывать отдельно для каждой валюты.

Пример:

```text
EUR: 3 420,00 €
RUB: 186 000 ₽
```

Суммы в разных валютах нельзя складывать без явного правила конвертации.

Данные должны поступать из тех же сервисов Digital Purchases, которые используются в профиле пользователя и финансовых представлениях.

## Переход из CRM Intelligence

Карточки CRM Intelligence могут показывать:

- профили риска;
- пробные периоды без покупки;
- неактивных пользователей;
- неуспешные платежи;
- диалоги без ответа.

Клик по показателю должен открывать User Explorer с уже примененными фильтрами.

## Техническая согласованность

Dashboard должен соблюдать архитектуру плагина:

- SQL находится в repositories;
- бизнес-логика находится в services;
- renderers и templates не выполняют SQL;
- доступ проверяется через `AdminSecurity`;
- общие маршруты берутся из `subscription_config`;
- чувствительные функции защищаются capabilities Moodle.

## Если данные выглядят неверно

Проверьте:

1. выбранный период;
2. часовой пояс Moodle;
3. статусы платежей;
4. планировщик задач;
5. кэш;
6. границы дат;
7. журналы плагина.

Не исправляйте значения прямо в шаблоне. Исправление должно выполняться в repository или сервисе, который формирует показатель.

## Рекомендации

Используйте **Сегодня** для оперативного контроля, **Текущую неделю** для ежедневной работы и **Текущий месяц** для отчетности.

Перед публикацией цифр проверьте период, валюту, включенные статусы платежей, время генерации и активные фильтры.
