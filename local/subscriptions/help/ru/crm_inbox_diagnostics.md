# Диагностика CRM Inbox

Страница диагностики CRM Inbox позволяет проверить получение и отправку писем, синхронизацию, вложения и работу ИИ-помощника.

Используйте диагностику до ручного изменения записей в базе данных или многократного перезапуска синхронизации.

## Перед началом

Для просмотра технической диагностики требуется право управления конфигурацией CRM.

Диагностика может показывать информацию о:

- настроенных почтовых аккаунтах;
- подключениях IMAP и SMTP;
- удалённых папках;
- запусках синхронизации;
- вложениях;
- ИИ-провайдере;
- квотах;
- кэше;
- последних ошибках.

Пароли никогда не отображаются в открытом виде.

## Диагностика IMAP

IMAP используется для получения писем.

Проверяются:

- наличие расширения PHP IMAP;
- активность аккаунта Inbox;
- наличие обязательных учётных данных;
- доступность удалённого сервера;
- успешность авторизации;
- наличие настроенных папок.

Ошибка IMAP может остановить получение новых писем, но уже импортированные диалоги останутся доступными.

### Частые причины

- расширение PHP IMAP не установлено;
- PHP-FPM не перезапущен после установки расширения;
- неверный пароль;
- неверный адрес сервера или порт;
- ошибка TLS;
- удалённая папка была переименована;
- провайдер отключил доступ IMAP.

## Диагностика SMTP

SMTP используется для отправки ответов.

Проверяются:

- доступность SMTP-сервера;
- авторизация;
- порт;
- шифрование;
- адрес отправителя.

Успешное подключение IMAP не означает, что SMTP также работает. Эти подключения проверяются отдельно.

## Синхронизация

Синхронизация Inbox является идемпотентной.

Одно и то же удалённое письмо не должно импортироваться несколько раз.

Основные счётчики:

- **получено** — письма прочитаны у провайдера;
- **создано** — новые сообщения сохранены в Moodle;
- **обновлено** — обновлены уже известные сообщения;
- **пропущено** — изменения не требовались;
- **ошибки** — сообщения не удалось обработать;
- **остались данные** — в удалённой папке есть дополнительные письма.

### Незавершённая синхронизация

Не запускайте сразу несколько синхронизаций одновременно.

Сначала проверьте:

1. активную блокировку;
2. размер пакета;
3. последний курсор;
4. количество ошибок;
5. состояние удалённой папки;
6. журнал плановой задачи.

CLI и cron могут продолжать обработку пакетами.

## Вложения

Вложения сохраняются через Moodle File API.

Диагностика может выявить:

- ошибку удалённого скачивания;
- пустое содержимое;
- неверный MIME-тип;
- слишком большой файл;
- ошибку хранения Moodle;
- недоступную удалённую ссылку.

Удаление диалога в CRM не равнозначно удалению письма у почтового провайдера.

## Контакты и привязка пользователей

Письмо может прийти от человека, которого ещё нет в CRM.

В этом случае:

- создаётся внешний контакт;
- диалог остаётся доступным;
- пользователь Moodle не создаётся автоматически;
- привязку можно выполнить позже.

Когда создаётся аккаунт CampusFR с тем же email, автоматическое сопоставление может связать контакт с пользователем.

Зафиксированная ручная привязка никогда не должна заменяться автоматически.

## Диагностика ИИ

Диагностика ИИ проверяет:

- активного провайдера;
- настройки OpenAI;
- выбранную модель;
- доступные возможности;
- дневные квоты;
- последние ошибки;
- кэш;
- локальный fallback.

Доступность провайдера не гарантирует корректность каждого ответа. Результаты проходят локальную проверку и Structured Outputs.

## Статусы результатов ИИ

Результат может иметь статус:

- **success** — корректный результат;
- **partial** — результат пригоден, но неполон;
- **failed** — результат отсутствует, некорректен или отклонён;
- **cached** — корректный результат загружен из кэша.

Некорректный ответ нельзя показывать как подтверждённую рекомендацию.

## Квоты

Могут применяться:

- общая дневная квота;
- дневная квота администратора.

После достижения лимита:

- новые удалённые запросы не отправляются;
- сохранённые результаты кэша могут оставаться доступными;
- основные функции Inbox продолжают работать без ИИ.

## Рекомендуемый порядок проверки

1. Откройте диагностику Inbox.
2. Проверьте IMAP и SMTP отдельно.
3. Посмотрите последний журнал синхронизации.
4. Проверьте ошибки вложений.
5. Запустите одну ручную синхронизацию.
6. Откройте диагностику ИИ, если проблема связана с анализом.
7. Проверьте квоты и провайдера.
8. Посмотрите журналы Moodle.
9. Запустите CLI-тесты плагина.

## Чего следует избегать

Не следует:

- вручную изменять курсоры синхронизации;
- удалять provider keys;
- очищать таблицы Inbox для устранения дублей;
- записывать пароли в журналы;
- отключать проверку результатов ИИ;
- запускать параллельные синхронизации;
- отправлять ИИ-подсказку без проверки человеком.

## Финальная проверка

После исправления:

- подключение IMAP должно быть успешным;
- подключение SMTP должно быть успешным;
- синхронизация должна завершаться без блокирующей ошибки;
- новое письмо должно импортироваться один раз;
- отправленный ответ должен появляться в истории;
- вложения должны быть доступны только уполномоченным пользователям;
- диагностика ИИ должна распознавать настроенного провайдера;
- ИИ-подсказку должно быть возможно изменить перед отправкой.
